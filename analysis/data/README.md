# analysis/data: the benchmark as three tables

Generated by `python3 analysis/collect.py` (stdlib only; it imports `runner/knee.py`,
which is stdlib only too, so run validity uses the runner's own rules). It only reads
`results/`. Re-run it and every CSV here is rewritten. It finishes with an assert
against the known Task 7 medians and prints `sanity check vs Task 7 medians: OK`.

| file | rows | one row per |
|---|---|---|
| `cells.csv` | 105 | (results_dir, workload, cell) |
| `runs.csv` | 225 | `run-N/` directory (every fixed run, valid or not) |
| `telemetry.csv` | 225 | `run-N/` directory (top.json, flamegraph.json, aperf report) |
| `skipped.txt` | 129 | file or dir the script saw and did not tabulate, with the reason |

Join key between the three: `results_dir, workload, cell` (+ `run`).

## Conventions

- `workload` is the **directory name** (`postgres-2x`, `mongo-ebs125` included). The
  parser used is chosen by the part before the first `-`. `cell_json_workload` /
  `cell_json_cell` hold what cell.json itself says (for `postgres-2x` it says
  `postgres`; for `mongo-ebs125/arm-tuned-interrupted` it says `arm-tuned`).
- `chip` = cell prefix (`arm` = m9g Graviton5, `amd` = m8a EPYC, `x86` = m8i Xeon 6).
  `variant` = the rest (`stock`, `tuned`, `tuned-vthreads`, `smtoff`, `t8`, `t15`,
  `tuned-kleidiai`, `tuned-interrupted`).
- `day_class`: `task7-d1|d2|d3` from the dir name; `*-cal-*` = calibration;
  `*-ab-*` = ab-test; anything else (`2026-09-04`) = early-lab.
- `set_aside` is non-empty for the two workload dirs the lab put aside (progress.md):
  `postgres-2x` (the fixed_clients_factor=2 runs, replaced by 1x after commit 960d17a)
  and `mongo-ebs125` (the EBS-bound mongo arm day-2 run). Filter them out for slides.
- Lists (invalid reasons) are joined with `; `. Dicts are JSON strings.
- Empty cell = not present in the source, never 0.

## Validity (same semantics as `runner/analysis/stats.py`)

A run is `valid` when it was measured (has k6.json / llama.json / ycsb.txt /
pgbench.txt / iperf.json) AND:
1. `meta.json` `invalid` is empty (the runner judged it live: loader saturated,
   cpuset, no summary, pgbench schedule lag, fine ladder failed...). meta is
   authoritative, as in stats.py.
2. otherwise the file is re-judged with today's rules: `knee.invalid_reasons`
   (k6/llama: failed > 1 %, dropped iterations > 0.25 %, p99 > SLO, delivered <
   95 % of `rate`) or `knee.ycsb_invalid_reasons` (READ p99 > SLO, TOTAL OPS <
   95 % of `target_ops`). The SLO is `knee.json slo_ms`; inference and net have no
   knee.json, so no SLO/rate check applies to them (as in stats.py).

`invalid_reasons` holds the union of both. Nothing is dropped from the CSVs; the
cell medians use valid runs only.

**Re-judged records** are flagged, not hidden: `invalid_before_rejudge` + `rejudged`
(per run in runs.csv; per cell in cells.csv, taken from cell.json or knee.json;
cells.csv `runs_invalid_before_rejudge` counts them). They are:
- 7 Java runs of task7-d1 (`amd-stock/run-1`, `arm-tuned-vthreads/run-1..3`,
  `amd-tuned-vthreads/run-1..3`): invalid at 0.10–0.12 % dropped iterations under
  the old 0.1 % rule, valid under R3 (0.25 %). They count as valid here.
- `2026-09-26-cal-pg-thp/postgres/{arm,amd}-tuned`: the knee was
  `ladder_never_crossed`, rejudged in b3094f3 to "peak at 256 inside the ladder".

## cells.csv

| column | source / derivation |
|---|---|
| results_dir, day_class, date | dir name; date = first 10 chars |
| workload, cell, chip, variant, set_aside | dir names (see Conventions) |
| instance_type, nodes, minutes, runs_requested | cell.json (instance_type falls back to the chip map; never needed) |
| has_cell_json, has_knee_json | file present |
| cell_invalid | cell.json `invalid` (the runner's cell-level reasons, e.g. "knee not usable") |
| invalid_before_rejudge, rejudged | cell.json or knee.json |
| app_env | cell.json `app_env` (the knob overrides the cell ran with) |
| llama_n_threads, llama_system_info | cell.json `llama_system_info[0]` (n_threads parsed out) |
| n_run_dirs / n_runs_measured / n_runs_valid | count of run-N dirs / with a load report / valid |
| headline_metric, headline_unit | go, java: `run_knee` rps; inference: `tok_s`; postgres: `fixed_ops` tps; mongo: `fixed_ops` ops/s; net: `gbps_fwd` |
| headline_median/min/max | over **valid** runs of runs.csv `headline_value` |
| headline_median_all_runs | same, ignoring validity (to see what the set-aside cells measured) |
| headline_source | `valid runs`, or `coarse knee.json (no valid run_knee)` for go/java cells with no valid run and a valid rps knee (stats.py's fallback for pre-fine-ladder results and knee-only calibration cells). Stricter than stats.py: no fallback when knee.json `invalid` is non-empty |
| p99_ms_median, delivered_rps_median, fixed_ops_median, gbps_rev_median, cpu_cores_per_gbps_fwd/rev_median, lag_p99_ms_median | median over valid runs of the runs.csv column of the same name |
| run_loader_peak_percent_max | max of meta.json `loader_peak_percent` over runs |
| run_invalid_reasons | `run-N: reasons` for every run with any |
| knee_unit_raw | knee.json `unit`: `rps` (k6 open-loop ladder) or `clients`/`threads` (pgbench/YCSB closed-loop ladder) |
| knee_throughput, knee_throughput_unit | rps ladders: knee.json `knee` (rps). closed-loop: knee.json `ops` (throughput at the knee step; the knee is the throughput peak under the SLO, THROUGHPUT_DROP = 5 %) |
| knee_step | knee.json `knee`: the rps step, or the client/thread count for PG/Mongo |
| slo_ms | knee.json |
| ended_by_kind/step/p99_ms/reason | knee.json `ended_by` (`crossing` = p99 over SLO, `throughput_drop` = ops < 95 % of the best step) |
| knee_invalid, knee_invalid_steps | knee.json `invalid`, `invalid_steps` |
| knee_loader_peak_percent, loader_guard_waived | knee.json (`why` text when the loader guard was waived because the SUT was saturated) |
| knee_series | knee.json `series` as JSON: `[[step, p99_ms], ...]` |
| pg_* | cell.json `postgres`: shared_buffers, effective_cache_size, max_connections, huge_pages, huge_pages_status, database_bytes, shmem_thp (knob on/off), shmem_enabled and shmem_huge_share after warm-up, shmem_huge_share after the ladder |

Important: for **go/java the Task 7 headline is `headline_median` (median of the
per-run fine-ladder knees)**, not `knee_throughput` (the coarse 5k/10k-step knee).
For **postgres/mongo the headline knee is `knee_throughput`** (one ladder per cell);
`headline_median` there is the throughput of the fixed runs held at 80 % of it.

## runs.csv

| column | source |
|---|---|
| run, has_meta | dir name; meta.json present |
| run_knee, rate | meta.json (go/java): fine-ladder knee of this run; rps offered in the fixed run (80 % of run_knee, rounded to the generator count) |
| target_ops, clients, knee_clients, threads | meta.json (postgres: clients = factor x knee clients, capped; mongo: threads) |
| loader_peak_percent, cpuset, cpuset_count, cstates_ready, aperf, flamegraph | meta.json |
| lag_p99_ms, lag_max_ms, pgbench_threads, pgbench_pod_cores_max | meta.json (postgres; pod cores = max over the pgbench pods) |
| mongo_documents, mongo_warmup | meta.json (mongo) |
| actuator | meta.json (java): HikariCP/Tomcat gauges, JSON |
| meta_invalid, invalid_before_rejudge, rejudged | meta.json |
| llama_n_threads | meta.json `llama_system_info` |
| p50/p90/p95/p99/p999/max/avg_ms | k6/llama: `http_req_duration` of k6.json / llama.json (merged from generators: every percentile is the MAX across generators, knee.merge_summaries). postgres/mongo: the **READ** line of pgbench.txt / ycsb.txt, us to ms (pgbench merge: exact histogram; ycsb merge: max across clients) |
| delivered_rps, requests, http_req_failed_rate, dropped_iterations, iterations, duration_s | k6.json / llama.json |
| llama_predicted_tokens, tok_s | llama.json: `llama_predicted_tokens.count / (testRunDurationMs/1000)` (stats.py's formula) |
| llama_slot_tok_s_med, llama_prompt_ms_med, llama_predicted_ms_med | llama.json per-request trends (median) |
| report_file, fixed_ops, read_ops, update_ops, update_p99_ms, pgbench_failed, pgbench_samples | ycsb.txt / pgbench.txt: TOTAL OPS (the headline), READ OPS, UPDATE OPS/p99 (mongo), Failed/Samples (pgbench) |
| gbps_fwd, gbps_rev | iperf.json / iperf-reverse.json `end.sum_received.bits_per_second / 1e9` (stats.py) |
| gbps_sent_*, retransmits_* | `end.sum_sent` |
| iperf_client_cpu_pct_*, iperf_server_sut_cpu_pct_* | `end.cpu_utilization_percent.host_total` / `remote_total`. The iperf3 server pod is on the SUT node (cell.py `server_node`), so `remote` = SUT. fwd = SUT receives, rev = SUT sends. These are iperf3's own process CPU %, not node CPU |
| net_cpu_baseline/fwd/rev_cores, net_cpu_notes | meta.json `net_cpu_cores` (SUT node CPU, median of the metrics-API windows wholly inside each window) |
| cpu_cores_per_gbps_fwd/rev | (net_cpu_{dir}_cores - baseline) / gbps_{dir}, per run (stats.py; it takes the median of this ratio) |
| fine_* | run-N/knee-fine.json: coarse_knee it started from, ended_by kind/step, invalid, loader_guard_waived |
| measured, invalid_reasons, valid | see Validity |
| headline_value | the per-run value the cell medians use (see cells.csv headline_metric) |

## telemetry.csv

| column | source |
|---|---|
| top_samples, top_source | run-N/top.json: sample count; `metrics-api` or `kubectl-top` (old runs, no windows) |
| top_node_cpu_cores/pct_median/max | top.json `node_cpu_millicores` / `node_cpu_percent` (SUT node) |
| top_pod_cpu_cores_median/max | top.json `pod_cpu_millicores` (the SUT workload pod) |
| top_loader_cpu_pct_median/max | top.json `loader_cpu_percent` (loader node) |
| flamegraph_exists | run-N/flamegraph.json present |
| flame_sample_rate, flame_units, flame_cpu_seconds, flame_distinct_frames | Pyroscope flamebearer: `numTicks / sampleRate` (numTicks are CPU nanoseconds, sampleRate 1e9) = CPU-seconds profiled for the service; distinct frame names. Raw numTicks is not written: a 12-digit integer reads as an account id to a sanitize grep |
| aperf_report, aperf_seconds, aperf_instance_type, aperf_cpus, aperf_kernel | run-N/aperf/aperf_record_*/aperf_record_report/data/js/{runs,systeminfo}.js (aperf_instance_type matches cell.json on all 225 runs) |
| cpu_{user,system,idle,iowait,irq,softirq,steal,nice,aggregate}_{avg,p50} | aperf `cpu_utilization.js` metric `stats` (Aggregate series, % of all 16 vCPUs, 1 s samples) |
| pmu_{metric}_{avg,p50} | aperf `perf_stat.js` metric `stats` (Aggregate series, 1 s samples): ipc, branch-mpki, data-l1-mpki, inst-l1-mpki, l2-mpki, l3-mpki, data/inst-tlb-mpki, data/inst-tlb-tw-pki, stall-frontend-pkc, stall-backend-pkc, code-sparsity, strex-spec-pki, data-st-tlb-* |

PMU availability (empty = the CPU/hypervisor does not expose the event; aperf writes
a 2-point all-zero placeholder series, which the script turns into empty, not 0):

| chip | available | empty |
|---|---|---|
| arm (m9g) | ipc, branch, L1d/L1i, L2, TLB miss + walk, stall front/back, code-sparsity, strex | l3-mpki (no data-st-tlb-* metrics at all) |
| amd (m8a) | ipc, branch, L1i, L2, TLB miss + walk, stall-frontend | data-l1-mpki, l3-mpki, stall-backend, code-sparsity, strex, data-st-tlb-* |
| x86 (m8i) | ipc, branch, L1d/L1i, stall-frontend only | L2, L3, all TLB, stall-backend, code-sparsity, strex, data-st-tlb-* |

So cross-chip comparisons are possible only for IPC, branch-mpki, inst-l1-mpki and
stall-frontend-pkc. Metric definitions differ per
vendor (aperf maps each to that PMU's events), so treat cross-vendor stall numbers
as indicative.

## Gaps and assumptions

- **No CPU frequency.** No aperf file on disk carries clock frequency (checked every
  data/js file of a report); only `kernel_config.js` mentions "freq". Nothing to extract.
- **aperf window vs load window.** aperf starts right before the fixed run and lasts
  `fixed_seconds` (480 s go/java/pg/mongo, 360 s inference). The avg/p50 include the
  first seconds of ramp (min is often 0). For **net**, aperf lasts 2 x 60 s = 120 s
  but the run is 60 s idle baseline + 60 s fwd + 60 s rev, so the aperf numbers cover
  **baseline + forward only, not reverse**. Use `p50` rather than `avg` when in doubt.
- **Old net run**: `2026-09-04/net` has no
  `net_windows`/`net_cpu_cores`, so `cpu_cores_per_gbps_*` is empty for it. stats.py's
  fallback (whole-run node median / fwd Gbps) can be rebuilt from
  `telemetry.top_node_cpu_cores_median / runs.gbps_fwd`; not done here.
- **2026-09-04 Java runs** are invalid in meta.json under the early rule
  (`dropped_iterations count > 0`); meta is authoritative, so they stay invalid even
  though today's 0.25 % rule might pass them. Their `headline_median` is the coarse
  knee (stats.py fallback), `headline_source` says so.
- **Calibration cells** mostly have a knee and no runs (`n_run_dirs = 0`); their
  number is `knee_throughput`. `2026-09-24-cal-j-x86-tiered` has an invalid knee
  (loader 98 %), so it gets no headline. `2026-09-04/mongo/arm-stock` never crossed.
- **Per-generator / per-client raw files are not tabulated**: `k6-g1/g2.json`,
  `knee-raw*.json`, `knee-fine-raw*.json`, `*-c1/c2.txt`. The merged files the runner
  itself judges (`k6.json`, `ycsb.txt`, `pgbench.txt`, `knee*.json`) are read instead.
- **Per-step ladder reports** (`knee-c*.txt`, `knee-t*.txt`) are not tabulated; the
  step series (p99 per step) is in `cells.knee_series`, the knee step's throughput is
  `knee_throughput`. Per-step throughput for every step would need those txt files.
- **knee.json per-step extras not tabulated**: `windows`, `loader_peak_by_step`,
  `sut_cpu_cores_by_step`, `pgbench_pod_cores_by_step`, `wait_events_by_step`,
  `actuator_by_step`, `jobs`, `threads`. meta.json `wait_events_by_step` (postgres),
  `net_windows` and `pgbench_jobs` are not tabulated either.
- **aperf files not read**: the `.tar.gz` archives, `aperf.log`, and the other report
  js (vmstat, meminfo, netstat, interrupts, diskstats, processes, memalloc,
  sysctl, kernel_config, ena_stat, `*_findings`). perf_profile.js/java_profile.js are
  empty (141 B) placeholders.
- **flamegraph.json**: only totals are extracted. Per-function shares need a query
  per frame (see `.superpowers/.../scripts/pyro_incl.py` for the inclusive-time walk);
  the PNG/SVG in `2026-09-27-task7-d3/flamegraphs/` are rendered images, skipped.
- **Set-aside cells** stay in the tables (flagged). `postgres-2x/arm-stock` runs are
  all invalid (pgbench schedule lag 0.5–1 s); `postgres-2x/arm-tuned` is 3/3 valid.
  `mongo-ebs125/arm-stock` is 0/3 (READ p99 ~23 ms, ~134k of 194k ops/s);
  `mongo-ebs125/arm-tuned-interrupted` has a cell.json and no runs.
- **Semantics guessed**: `day_class` and `variant` are derived from names only.
  `iperf_*_cpu_pct` host/remote mapping relies on the iperf3 server always being the
  SUT (it is, per cell.py `server_node`).
- `skipped.txt` lists every file/dir walked and not tabulated: `cluster.json` and
  `ecr.json` (account id / ARNs, never opened), `ledger.md`, `run*.log`, `logs/`,
  `flamegraphs/`, `inventory*/` (2026-09-24 and 2026-09-28-final-snapshot are
  inventory-only days), the early-lab `knee-attempt*.json`, and three calibration
  side-outputs with no cell structure: `loadercheck.json` (2 dirs),
  `mongo2client.json`, `tickets.jsonl(.stop)`.
